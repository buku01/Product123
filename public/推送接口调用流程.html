推送接口调用流程

APP/H5、后台、子平台的推送均由平台后端服务统一转发至起聊。

需求背景

部分攻击者已发现并利用推送接口漏洞，向玩家发送未经授权的消息。为限制推送接口的调用来源，起聊需对调用方公网出口 IP 进行白名单校验，拦截非白名单 IP 的推送请求。同时，APP/H5、后台、子平台的推送均需经过平台后端服务，由平台后端服务完成权限及参数校验后统一转发至起聊，并完成平台后端服务公网出口 IP 加白。

需求描述

  1. 起聊推送接口启用 IP 白名单校验，未加白 IP 发起的推送请求将被拦截。
  2. APP/H5 的模拟用户、模拟客服、模拟客服批量推送，对应图中三个方法，均需通过平台后端统一转发至起聊。
  3. 后台、子平台的推送也需由平台后端服务统一转发至起聊，转发前完成权限及参数校验。
  4. 平台后端服务的实际公网出口 IP 需提前完成加白；多个出口需全部加白，出口变更时同步更新。
  5. 各调用服务应反馈实际推送结果；IP 拦截、接口异常或超时应明确返回失败，批量推送应准确反馈处理结果。

接口范围说明：图中的三个具体方法仅归属于 APP/H5 分支。后台、子平台的推送均经平台后端服务转发，对应的起聊接口按各自业务确定。各发起端与平台后端服务之间的接口地址及参数由联调确认。
