后台需求说明

一、配置位置与保存

适用类型：银行卡、支付宝、数字人民币、微信、QQ。类型栏已用红框标出，各类型需支持本次新增配置。

保留原后台样式及已有字段。新增“防诈骗文字确认”和“取款进度页防诈图”两组配置，位于原图片上传下方，通过底部“保存”提交。

未保存的修改不影响前端。非法值提示错误，并保留上一份有效配置。

二、文字确认触发规则

  1. 先沿用原防诈骗提示的触发条件；上方“防诈骗提示”关闭时，文字确认不生效。
  2. 文字确认开启，且提现金额 ≥ 门槛、玩家当日已完成次数 < N，才要求输入文字。
  3. 未达金额门槛、已达每日上限或文字确认关闭时，若原防诈骗提醒仍触发，则读秒 3 秒后直接确认。

文字确认关闭时，下方参数禁用并保留原值，重新开启后可继续使用。

三、字段校验

触发提现金额
必填，≥ 0，最多两位小数；含边界。0 表示不限制金额门槛。
输入确认文字
1–60 字，不含换行或首尾空格。前端不预填，完整输入且完全一致后才启用确认；支持中文输入法。
每日输入次数 N
0–99 的整数，按玩家分别统计。0 表示不要求文字输入，保留原读秒确认。

四、次数与后续页面

文字正确且点击确认后才累计 1 次；读秒确认、错误输入、取消或刷新不累计。不以提现成功次数代替文字确认次数。

每日按平台业务时区 00:00 清零。文字确认后的提现失败，不回退已完成次数。

确认后进入“提现处理中”订单页。同一申请的重复提交不得重复计数。

五、取款进度页防诈图

与原“上传防诈骗图片”独立：原图用于取款前弹窗，新图用于订单页的取款信息与取款进度之间。

  • 填写有效 HTTP / HTTPS 图片地址并保存后显示；留空保存则隐藏区域，不留空白占位。
  • 确认到账、提现处理中及文字确认后的订单页共用此配置。
  • 不受文字确认开关、金额门槛和每日次数影响。加载失败则隐藏。

测试 / 技术对照

优化一 · 前端需求说明

适用与触发

适用于银行卡、支付宝、数字人民币、微信、QQ。先满足原防诈骗提示触发条件，再判断文字确认规则。

文字确认开启、提现金额 ≥ 配置门槛，且当日已完成次数 < 每日上限时，展示文字输入；其他情况保留 3 秒读秒确认。

页面与交互

  1. 保留防骗海报，实际进入先读秒 3 秒，不可提前确认。
  2. 需要文字确认时，读秒后显示输入区域，确认文字取自后台，不预填。
  3. 输入完全一致才启用“确认”；空白、错误或中文输入法尚未完成输入时不可提交。
  4. 读秒确认分支不显示输入框，倒计时结束后启用“确认”。
  5. 确认后进入提现处理中订单页。

次数与异常

文字正确且点击确认后累计一次；仅读秒确认、取消、输入错误或刷新不累计。同一申请重复提交不得重复累计。

每日按平台业务时区清零。已达上限后，再次申请仅读秒；次日重新判断。

重点测试

  • 金额等于门槛应命中；低于门槛仅读秒。
  • 每日次数从 N−1 变为 N 后，再次申请不要求输入。
  • 每日次数为 0，或文字确认关闭时仅读秒。
  • 修改后台文字并保存，新申请展示新文案。
  • 核对确认后订单页及防诈图联动。

优化二 · 前端需求说明

适用与展示位置

适用于银行卡、支付宝、数字人民币、微信、QQ。在“取款信息”与“取款进度”之间展示后台配置的“取款进度页防诈图”。

确认到账、提现处理中及优化一确认后进入的订单页共用配置。

展示规则

  • 配置有效图片地址并保存后展示。
  • 未配置或清空地址保存后隐藏，区域不留占位。
  • 加载失败时隐藏，不显示破损图标。
  • 图片不受文字确认开关、金额门槛或每日次数限制。

布局与原页面

图片宽度适配页面，保持内容完整，图上下间距紧凑。原有订单信息、进度、状态横幅和到账操作保持原逻辑。

图片直接读取后台配置的网络地址；当前横幅图仅在展示时裁去自带的上下空白，不修改原图。

重点测试

  • 两种订单状态的图片内容与位置一致。
  • 有效地址展示；空地址、404、图片无法解码时隐藏。
  • 从有图切换为空，保存后前端不留空白。
  • 关闭文字确认后，已配置图片仍正常展示。
  • 检查不同屏幕宽度下图片及订单操作布局。
